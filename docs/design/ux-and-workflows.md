# Windows 桌面 UX、信息架构与批量工作流规范

**USS-UX-001｜v0.1.0-draft｜2026-10-08｜Design Review**

## 1. UI 原则
面向维护很多 scripts 的用户，设计成专业桌面维护台而不是一次性聊天窗口。首要操作是**检查状态、批量诊断、修复预览、验收与回滚**。应用不应因为数据量很大而隐去失败脚本，也不应把“建议补丁”“已经应用”“已经验证功能”混合成一个成功状态。

技术建议 Electron + React + TypeScript；最小目标视窗建议 1280×800，兼容 100%/125%/150% DPI、窗口缩放、键盘操作和 Windows 暗色/浅色模式。支持简体中文为首发语言，界面字符串通过 i18n key 管理，英文可以后期扩展。所有日期存 UTC，按本地时区显示并清楚标明。

## 2. 应用导航
1. **总览 Dashboard**：脚本总数、已检/未检、失效确认、怀疑、受阻、已提议补丁、已应用、已验证、上次健康状态、AI 花费。
2. **脚本库 Library**：树形目录、列表、搜索、筛选、多选、右键动作、导入/拖放/文件夹扫描、来源与版本。
3. **批量任务 Jobs**：待运行/正在运行/暂停/失败/受阻/已完成、进度、批次策略、单条重试/跳过、并发控制。
4. **故障与证据 Diagnostics**：按域名/脚本/日期/错误类别/严重性，显示源行、旧选择器与现场证据。
5. **修复工作台 Repair**：候选选择器、评分分项、DOM 预览、AST 定位、左右 diff、审批与 V0-V4 级别。
6. **网站与兼容层 Sites & Compatibility**：site mapping、可访问目标 URL、页面状态、共享 role、受影响脚本、版本。
7. **浏览器 Browser**：Chrome 多配置、当前 CDP session、target 列表、连接状态、端口、失败排错。
8. **功能测试 Tests**：测试契约管理、无副作用/有副作用类型、测试历史、失败证据及 manager 真实环境验证。
9. **版本与恢复 Revisions**：修复历史、备份、比对、回滚预览、恢复 hash 结果。
10. **AI / 设置 Settings**：Provider、Base URL、key、模型、预算、脱敏策略、保留策略、输出路径、外观/语言、系统诊断。

首发 UX 可将 6/8 合并至站点详情、将 9 合并至脚本详情，但数据和入口不能丢失。

## 3. 主要页面细则
### 3.1 首次运行 Setup
- 欢迎和隐私摘要（所有脚本默认本地处理）。
- 选择 `chrome.exe` 或 portable launcher（真实执行文件识别、可更换）。
- 展示默认 `127.0.0.1:9223`，解释不会默认加入 `--user-data-dir`。
- 点击“检测连接”后显示版本、实际 PID、端口、目标页面清单、详细失败码。
- 成功后导入第一组 `.user.js`；不强制配置 AI。
- 首次真实浏览器测试需展示“允许访问当前页面 DOM”确认，不能用 setup 同意替代具体网站授权。
- 可以先跳过浏览器，直接使用 AST 静态检查。

### 3.2 脚本库
表格列：checkbox、脚本名称、当前版本、来源路径、目标域名、源码行数、Selector 数、动态未知数、静态状态、最近运行时状态、最近验收等级、最近检查时间、可修复候选数、备份状态、操作。

固定动作：导入文件 / 导入文件夹 / 拖放 / 重新扫描 / 分析所选 / 运行网站检查 / 诊断故障 / 为所选生成修复建议 / 查看历史 / 导出报告 / 从列表移除（不删除原文件）。危险操作必须明示是“移除索引”还是“删除文件”。

去重：相同路径重复导入时更新索引；不同路径相同 hash 展示“相同内容的另一副本”，不静默合并。批量选择保持跨页状态并明确显示选择 N 项。

### 3.3 批量任务
顶部摘要必须**分别**显示任务数、成功静态解析、动态验证通过、修复候选、已应用、已完成指定功能验证、受阻与失败，不允许一个“已修复 N”汇总混淆。表格列：
`task index | script | site state | phase | status | progress | error code | attempts | test level | result link`。

批量模式：`Scan Only`、`Diagnose`、`Propose`、`Validate`、`Apply Approved`。默认 `Scan Only`。启动前摘要展示输入个数、目录总文件数、有效脚本数、预计测试站点、Chrome 浏览器配置、是否将修改文件、是否将调用 AI、最多 AI 请求数和费用上限。

按钮：开始、暂停、恢复、取消、仅重试失败、导出报告。用户取消时尽量停止尚未执行的动作；“已产生网页副作用的步骤不可自动撤销”必须标注。任务重新运行时不自动重新应用相同 patch。

### 3.4 Repair 工作台
上方问题卡：失败类别、异常详细、证据质量、source range、site-state、session、旧版本。
左侧源代码只读 diff，按行号精确 highlight；右侧 DOM locator 候选排名、分项评分、唯一/可见/role、frame、shadow、网页状态/语言、历史匹配与截图（如已授权）。
中段显示 patch 的精确编辑位置、变动字符数、是否改变权限、关联依赖及风险提示。
底部按顺序排列 V0-V4 测试明细和按钮：“重新收集证据”“生成候选”“重新测试”“接受修复”“拒绝”“备份并应用”“回滚”。未满足门槛时禁用应用并提供明确原因（如 “V3 没有配置，不可自动功能验收”）。
AI 修复按钮不是默认主按钮；要显示将发送的字段、字节数、目标 Provider、请求上限和可能费用。

### 3.5 Browser 页面
分两块：
- **已配置浏览器**：别名、文件路径、真实版本、进程/launcher 类型、调试地址、端口、最近成功/失败日期；新增、复制、编辑、删除、设默认。
- **实时连接**：实际身份、CDP protocol、target 列表、Session ID（可复制时脱敏）、所选页面与 frame、握手诊断。
连接失败时按错误码推荐：路径无效、端口冲突、Chrome 已运行、参数未转发、Chrome136+ profile 限制、WebSocket 被阻断、CDP 协议不兼容。
“不使用 --user-data-dir”必须作为默认设置明确显示；用户选择隔离 profile 是独立高级操作，展示完整参数并获得授权。

### 3.6 Health Dashboard
区分 `上次检查时正常` / `当前已验证`；按脚本每行显示：最近 V1/V3/V4、首次失败时刻、最近成功时刻、失败类型趋势、site selector drift、受影响兼容层、告警未读状态。健康状态不应随时间自动显示“健康”而未重新检查。

### 3.7 Compatibility
选择网站 → 页面状态 → Semantic roles（例如 chat.composer、chat.sendButton）→ 各个 locators 的策略、优先级和版本 → 依赖脚本 → 预览风险 → 受控发布。用户需要看到“更新这一个角色会影响 X 个脚本”，并能在新版本失败时快速恢复上一个兼容层版本。

### 3.8 Revisions
时间轴：`imported`→`proposed`→`approved`→`applied`→`validated`→`rolled_back`，各状态不得伪造。每一版本展示哈希、diff、关联问题、验收等级、备份状态、申请者和时间。回滚前二次确认当前脚本 hash 与事务基础版本；外部已被编辑需冲突处理而非强行覆盖。

## 4. 状态颜色和语义
使用颜色+图标+文字，不只靠颜色：
- neutral：未验证、尚未执行、已排队；
- informative：分析中、需要运行时确认；
- warning：怀疑失效、等待审查、运行受阻；
- error：故障确认、测试失败、恢复失败；
- success：明确对应 Vx 验收已通过（必须标注等级与时间）。
禁止展示“修复成功”而详情只证明匹配一个 DOM 元素。

## 5. 关键流程
```text
A. 初次使用
选 Chrome → 验证 CDP → 导入文件夹 → AST → 配置 site mapping → Diagnose
B. 批量诊断
选脚本 → 选站点/状态 → 检查授权 → 队列运行 → 看证据/受阻 → 导出
C. 本地修复
Finding → 生成候选 → 查看范围+风险 → V0-V3 → 审核 → 备份并应用 → 验证 → 版本
D. AI 补救
本地候选不足 → 预览脱敏上下文 → 用户批准外发 → 模型建议 → 本地 V0-V4 → 审查
E. 兼容层更新
一个站点 role 漂移 → 更新版本 → 扫描依赖 → 全部相关测试 → canary → 发布/回滚
F. 回滚
选择 Revision → 对比当前 hash → 显示恢复文件 → 审核 → 恢复 → hash 验证
```

## 6. 界面文案规范
- “分析完成”：表示静态 AST 完成，不是网页测试。
- “需要运行时确认”：明确不可从源码算出动态 selector。
- “有修复建议”：未写入源码。
- “已应用修复”：成功完成文件写入；旁边单列“最高通过 Vx”。
- “功能通过”：必须展示哪一个 Test Case ID、结果和时间。
- “无法检测”：必带原因，例如目标页未登录、站点拦截、CDP 不可用、扩展未安装。
- “未知”：信息缺少；与“不存在”区别。

## 7. 无障碍与键盘
表格支持 Ctrl+A 选择当前过滤内项目（确认选择范围）；Enter 查看详情、Ctrl+F 搜索、Esc 取消模态。危险写入用明确文本确认；检查屏幕阅读器标签、键盘焦点、图标可解释性和颜色对比；长代码 diff 具有复制、折叠上下文及行号跳转。

## 8. 首发验收示例
- 导入 50 个脚本，其中 2 个无效：列表显示 48 parsed/2 invalid，不漏任一文件。
- 20 个脚本诊断：10 通过 V1、3 有候选、4 因登录被阻断、3 无测试；总览不显示“20 个修复完成”。
- 误选另一 Chrome 的 9223：连接页提示 identity_uncertain 并阻断网页写动作。
- L3 提议变更元数据 `@grant`：Repair 页面显示越权风险并禁止自动应用。
- 共享角色影响 5 个脚本：发布前明确显示 5 个依赖和回归列表。
